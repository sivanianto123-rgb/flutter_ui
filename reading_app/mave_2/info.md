# Mave — App Development Log

## What Is Mave?

Mave is a Flutter reading app for toddlers aged 0–2. It focuses on phonics and syllable recognition through interactive, audio-driven games. The core experience is the **Sound Mode**, a 4-level progression that teaches a single syllable (e.g. "ma") through listening, matching, hunting, and story narration.

| Layer | Choice |

## What Has Been Built

### Core Services

**`GeminiTTSService`**
- Calls the `gemini-2.5-flash-preview-tts` model via the v1beta REST endpoint
- Returns raw 16-bit PCM (mono, 24 kHz little-endian) wrapped in a 44-byte RIFF/WAV header so `just_audio` can play it directly
- Disk caches every generated file using SHA-256(text|voice) as the filename under `mave_tts_cache/`
- Cache survives app restarts (uses Documents directory, not temp)
- `hasCached(text)` lets callers check disk before making an API call
- Prompt wraps short inputs: `"Pronounce the phonetic sound clearly: $text..."` to prevent the model from producing no output on single-syllable words
- Retry logic: if `finishReason != "STOP"`, retries once with a slightly different prompt
- All 4 harm categories set to `BLOCK_NONE` so phonetic sounds like "ma" or "ba" don't trip content filters

**`AudioService`**
- Manages two `AudioPlayer` instances: one for main narration, one for overlapping SFX
- `preload(List<String>)`: fetches and caches a list of phrases sequentially; skips in-memory hits, skips disk-cached files without delay, waits 3 seconds after any real API call to stay within Gemini rate limits
- `speak(text)`: plays a phrase immediately, using the preloaded cache if available
- `speakSequence(texts)`: plays multiple phrases in order with a configurable gap
- `waitForCompletion()`: awaits `ProcessingState.completed` with a 20-second timeout

**`AppProviders`**
- `geminiTtsServiceProvider`, `audioServiceProvider`, `geminiLlmServiceProvider`
- `childProfileProvider`: Riverpod `StateNotifier` backed by Hive — stores name, per-syllable level progress, and total stars
- API key injected at compile time via `String.fromEnvironment('GEMINI_API_KEY')`

**`ChildProfile` (Hive)**
- `HiveType(typeId: 0)`, pre-generated `TypeAdapter` (no build_runner needed at runtime)
- Fields: `name`, `levelProgress: Map<String, int>`, `totalStars: int`

### Sound Mode — 4 Levels

The Sound Mode is a `PageView` with `NeverScrollableScrollPhysics`. Navigation is manual via a **Next button** that only appears after the level's primary audio finishes (`audioReady` state flag). A 1-second debounce prevents accidental double-taps.

**Level 1 — Listen & Watch**
- A large rounded card displays the syllable split into individual letters (e.g. "M" and "A")
- Each letter animates (scale + color) in sync with the TTS playback phase: full word → consonant → vowel
- `PlayingPhase` enum drives the animation: `idle`, `full`, `consonant`, `vowel`
- A microphone indicator pulses and listens for any toddler vocalization via `speech_to_text`; a sound level above -20 dB triggers a celebration star (no auto-advance — parent taps Next)
- Card is constrained to `maxWidth: 800` for iPad/TV layouts
- Background preloads Level 2 audio (fire-and-forget) while the child is on this screen

**Level 2 — Animal Match (Drag & Drop)**
- Three animal cards: Cat → "ba", Dog → "da", Cow → "ma"
- A draggable word bubble sits at the bottom; the child drags it onto the correct animal
- Correct drop: card turns green, success banner appears, audio plays, Next button unlocks
- Wrong drop: card flashes red + `shakeX` animation for 650ms, then resets
- Animal cards use `Expanded`/`Flexible` in a Row to prevent overflow on small screens

**Level 3 — Bubble Hunt**
- 9 bubbles scattered across the screen (3 targets + 6 distractors)
- Positions generated with a seeded RNG (seed=42) and a minimum 112dp gap between centers to prevent overlap; falls back to a grid on very small screens
- Bubbles are 100×100dp minimum for toddler/iPad touch safety
- Tapping any bubble plays its sound; tapping a target triggers a pop explosion animation (`PopExplosionPainter`)
- Screen completes when all 3 target bubbles are found

**Level 4 — Story Time**
- A short story containing the target syllable is generated by Gemini LLM and stored in `SoundModeState.storyText`
- The story is narrated sentence-by-sentence; the currently narrating sentence pulses with a scale animation
- Target syllable occurrences are highlighted in the story text using `RichText` + `RegExp.allMatches`
- On completion: awards a star, updates `levelProgress` in Hive, shows "Level Complete"

**Navigation**
- `MaveNextButton`: 96dp amber circle with an infinite pulse animation; isFinish variant is green with a home icon
- Placed as `Positioned(bottom: 24, right: 24)` inside a `Stack` on every level screen
- `PageController.nextPage(600ms, Curves.easeInOut)` transitions between levels

**Background**
- `AnimatedBubbleBackground`: `CustomPainter` drawing 12 floating pastel bubbles (seed=42), animated on an 8-second loop

## Issues Faced & How They Were Resolved

### 1. TTS Model & Endpoint Change
**Problem:** Initial code targeted an older Gemini model.  
**Fix:** Updated to `gemini-2.5-flash-preview-tts` on the `v1beta` endpoint. Added WAV header wrapping (44-byte RIFF) because the API returns raw PCM, which `just_audio` cannot play directly.

### 2. `NoSuchMethodError` on TTS Response
**Problem:** Code crashed drilling into `candidates[0]['content']['parts']` when any key was null.  
**Fix:** Full null-safe drill-down at every level: `candidates`, `content`, `parts`, `inlineData`, `data`. Each step is guarded with `as Type?` and a null check before throwing a descriptive `GeminiTtsException`.

### 3. `inline_data` vs `inlineData` (snake_case vs camelCase)
**Problem:** Code looked for `inline_data` but the API returns `inlineData`.  
**Fix:** Corrected key to `inlineData`. Added logging of the full response body on any parse failure to catch similar mismatches quickly.

### 4. `finishReason: "OTHER"` on Short Words
**Problem:** Single syllables like "ma", "ba" caused the model to return `finishReason: "OTHER"` with no audio — the content filter was treating them as incomplete or harmful input.  
**Fix (three-pronged):**
- Prompt wrapping: `"Pronounce the phonetic sound clearly: $text..."` gives the model context
- Safety settings: all 4 harm categories set to `BLOCK_NONE`
- Retry: if `finishReason != "STOP"`, retries once with a slightly different prompt using explicit quote marks

### 5. 429 Rate Limit Errors from Parallel Preloading
**Problem:** `Future.wait` fired all TTS API calls simultaneously, hitting Gemini's rate limit.  
**Fix:** Replaced with a sequential loop. Checks disk cache first (`hasCached`). Only waits 3 seconds after a real API call — disk-cached and in-memory hits are instant.

### 6. `FormatException: Invalid group (?i)` in Regex
**Problem:** Used `RegExp('(?i)($syllable)')` with `.split()` to highlight syllables in the story. Dart's regex engine does not support inline flags like `(?i)`.  
**Fix:** Replaced with `RegExp(RegExp.escape(syllable), caseSensitive: false)` and used `.allMatches()` to build `RichText` spans manually.

### 7. `RenderFlex` Overflow on Level 2
**Problem:** Fixed-width animal cards in a `Row` overflowed on small phone screens.  
**Fix:** Wrapped each card in `Flexible` and the `Row` in `Expanded`, letting cards share available space proportionally.

### 8. `speech_to_text` Android Gradle Incompatibility
**Problem:** `speech_to_text: ^6.6.2` had an Android Gradle plugin incompatibility.  
**Fix:** Upgraded to `^7.0.0`.

### 9. `unnecessary_underscores` Lint Warning
**Problem:** Dart linter flagged `(_, __, ___)` style ignore parameters.  
**Fix:** Replaced with named but unused parameters: `(context, _, __)`.

### 10. `const_with_non_const` in Level 4
**Problem:** `const PlayerState(false, ProcessingState.idle)` used `const` on a non-const constructor.  
**Fix:** Removed `const`.

### 11. `body_might_complete_normally_catch_error` in Level 4
**Problem:** The `.catchError` handler in the narration timeout didn't return a value.  
**Fix:** Added explicit return value to the handler.

### 12. Next Button Layout / Overflow
**Problem:** The Next button was inline in each level's `Column`, causing overflow and taking up reserved space even when hidden.  
**Fix:** Restructured every level screen's `Scaffold` body to be a `Stack`; the Next button is `Positioned(bottom: 24, right: 24)` and simply absent from the tree when not yet visible (no placeholder `SizedBox` needed).

### 13. iPad/TV Layout on Level 1
**Problem:** The syllable card stretched to fill wide screens, looking disproportionate.  
**Fix:** Wrapped in `Center(child: ConstrainedBox(constraints: BoxConstraints(maxWidth: 800)))`.
